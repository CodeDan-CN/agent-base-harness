# 模型管理详细设计

## 1. 产品范围

模型管理是当前用户配置 Agent 推理服务的完整模块。V1 包含：

- 模型服务新增、编辑、启停和归档。
- API Key 等凭据设置、替换和清除。
- 使用草稿配置进行连接测试。
- Provider 模型列表发现、差异预览和选择性应用。
- 模型手工添加、能力与参数维护。
- 用户默认 Agent 模型选择。
- 配置 revision、缓存失效和 Step 不可变快照。

V1 首批正式 Adapter 为 OpenAI-compatible 和 Anthropic Messages-compatible。参考 UI 出现的其他 Provider 类型只有在对应 Adapter 和 Contract Test 完成后才能显示为可选择项。

## 2. 领域对象

### 2.1 ModelService

```ts
interface ModelServiceConfig {
  id: ModelServiceId;
  userId: LocalUserId;
  name: string;
  providerType: 'openai-compatible' | 'anthropic-compatible';
  endpoint: string;
  providerEndpoint?: string;
  credentialRef?: CredentialRef;
  status: 'enabled' | 'disabled' | 'archived';
  config: {
    requestHeaders?: Record<string, string>; // 禁止覆盖授权和安全保留头
    timeoutMs: number;
    organization?: string;
  };
  configVersion: number;
}
```

地址规范：

- 保存前去除尾部无意义 `/`，不对用户地址做不可逆猜测。
- OpenAI-compatible Adapter 明确计算 chat/responses/models 路径，不能在多个调用点拼接。
- Anthropic-compatible 可以设置独立 Messages endpoint；为空时按 Adapter 规则使用主地址。
- 只允许 `http`/`https`。是否允许非 localhost 明文 HTTP 由安全设置和发布平台 ADR 决定。
- 自定义 header 名和值执行长度、换行和保留字段校验。

### 2.2 Model

```ts
interface ModelConfig {
  id: ModelId;
  userId: LocalUserId;
  serviceId: ModelServiceId;
  remoteModelId: string;
  displayName: string;
  source: 'discovered' | 'manual';
  status: 'enabled' | 'disabled' | 'archived';
  contextWindow: number;
  maxOutputTokens: number;
  capabilities: {
    text: true;
    toolCall: boolean;
    vision: boolean;
    reasoning?: boolean;
    streaming: boolean;
  };
  defaultParameters: {
    temperature?: number;
    topP?: number;
    reasoningEffort?: string;
  };
  configVersion: number;
}
```

Provider 返回的模型列表通常不能可靠给出 contextWindow 和全部能力，因此发现只建立候选；关键运行参数必须来自已确认本地配置或项目内明确的 Provider metadata，不允许凭模型名猜测后静默保存。

## 3. Credential 设计

数据库只保存：

```text
credential_ref
credential_status = configured | missing | invalid
optional_mask = ****abcd
```

Credential Store key namespace：

```text
<application-id>/user/<userId>/model-service/<serviceId>/api-key
```

规则：

- Query 不返回明文。
- 编辑页面初始密钥输入为空；“已配置”是独立状态。
- 用户新输入值可在 Renderer 本地切换可见性，但保存后立即清空。
- 替换凭据先写新 secret，再事务更新 ref；失败时保持旧配置可用。
- 清除凭据前检查服务是否仍启用或为默认模型来源，并给出影响提示。
- 日志、错误、连接测试响应和诊断导出统一脱敏 Authorization/header/query secret。

## 4. 连接测试

连接测试可以使用尚未保存的服务草稿：

```ts
interface ModelServiceTestResult {
  status:
    'success' | 'auth_error' | 'network_error' | 'timeout' | 'protocol_error' | 'capability_error';
  latencyMs?: number;
  normalizedEndpoint: string;
  providerInfo?: string;
  discoveredModelCount?: number;
  message: string;
}
```

测试步骤：

1. 校验 URL、Provider 类型、超时和 credential mutation。
2. 在 Worker 中构造临时 Adapter，不写数据库和 Registry。
3. 优先执行轻量身份/模型列表请求；Provider 不支持时使用最小非流式或协议探针。
4. 读取响应后立即释放连接与临时 secret 引用。
5. 映射稳定错误分类，原始响应正文默认不返回 Renderer。

连接测试成功不自动保存服务；保存成功也不等同于真实 Provider 永远可用。

## 5. 模型发现与差异应用

发现流程：

```text
选择服务
→ 使用当前保存配置或明确草稿测试
→ Provider Adapter 拉取远端模型 ID
→ 与本地 (userId, serviceId, remoteModelId) 对比
→ 返回新增、已存在、远端缺失三类预览
→ 用户选择应用项
→ 事务更新 models 与 model_revision
```

规则：

- 发现结果使用短期 discoveryToken，绑定 userId、serviceId、服务 configVersion 和结果摘要。
- 服务配置在预览后改变则 token 失效。
- 远端缺失模型不自动删除，只标记提示；用户决定停用或归档。
- 已存在模型的手工 contextWindow、能力和默认参数不被远端空字段覆盖。
- 新发现模型默认 `disabled`，用户确认关键参数后启用；如果产品决定默认启用，必须在 UI 明确展示未确认能力风险。

## 6. 默认模型

设置默认模型前同时验证：

- Model 和 ModelService 均属于当前 userId。
- 两者均 `enabled` 且未归档。
- credential 已配置或 Provider 明确不需要 credential。
- Model 支持 streaming；Agent Tool 场景还需要 toolCall。
- contextWindow、maxOutputTokens 和预算参数合法。

无有效默认模型时：

- 可以浏览历史、管理配置和 Skill。
- `input.submit` 可以接纳还是直接拒绝必须统一。V1 选择在 Input Admission 阶段返回 `CONFIGURATION_INVALID`，不创建一个注定无法执行的 Queue 项。
- 不允许自动回退到另一用户、另一服务或列表第一项。

## 7. 保存、停用、归档

### 7.1 保存事务

```text
校验 expected model_revision
→ 处理 credential mutation
→ 写 model_services/models/user_model_settings
→ model_revision + 1
→ commit
→ 发布 configuration.changed(model)
→ 使当前用户 Model Registry 缓存失效
```

### 7.2 引用保护

- 当前默认模型不能直接归档，必须先选择新默认模型或明确进入无默认模型状态。
- 被 Session 固定配置引用的 Model 不能物理删除。
- 被历史 `request.context` 引用的 Model/Service 保留最小展示元数据并归档。
- 停用服务阻止新 Step，不取消已启动的 Provider 请求。
- 运行中的 Step 使用 ModelConfigSnapshot；配置保存不会改写 snapshot。

## 8. ModelConfigSnapshot 解析

```ts
function resolveModelSnapshot(scope, modelId?): ModelConfigSnapshot {
  // 1. 读取同一事务视图中的 model_revision、默认/指定 Model 和 Service
  // 2. 校验 userId、状态、能力和参数
  // 3. 解析 credentialRef，不读取到 Renderer
  // 4. 规范化 Provider Adapter 参数
  // 5. 计算 stable snapshotId 与 promptEpoch
  // 6. 返回不可变对象
}
```

Snapshot ID 的摘要输入包括：

- userId、modelRevision。
- serviceId、service configVersion、Provider 类型和规范化 endpoint。
- modelId、model configVersion、能力和请求参数。
- credentialRef 的稳定版本标识，但不包括明文。
- Runtime 中影响 Prompt/Adapter 的版本。

## 9. UI Snapshot

```ts
interface ModelManagementSnapshot {
  userId: LocalUserId;
  revision: number;
  services: Array<{
    id: string;
    name: string;
    providerType: string;
    status: string;
    modelCount: number;
    agentReady: boolean;
    credentialStatus: 'configured' | 'missing' | 'invalid';
  }>;
  modelsByService: Record<string, ModelListItem[]>;
  defaultModelId?: string;
}
```

页面必须覆盖：空列表、加载、保存、测试、发现、部分失败、revision 冲突、无默认模型、归档阻断和用户切换。

`agentReady` 是确定性派生值：服务启用、凭据满足、至少一个已启用模型且默认/可选模型满足 Agent 必要能力；不能由 UI Mock 布尔值保存。

## 10. Provider Adapter Contract

```ts
interface LlmProviderAdapter {
  testConnection(
    input: ProviderConnectionInput,
    signal: AbortSignal,
  ): Promise<ModelServiceTestResult>;
  listModels(input: ProviderConnectionInput, signal: AbortSignal): Promise<RemoteModelDescriptor[]>;
  stream(input: NormalizedModelRequest, signal: AbortSignal): AsyncIterable<NormalizedModelEvent>;
}
```

Contract Test 覆盖：

- 文本 chunk、Tool Call 增量和多个 Tool Call。
- usage、cache usage、reasoning usage 和 finish reason。
- 正常完成、输出截断、认证失败、限流、超时、断流和取消。
- 模型列表支持与不支持。
- URL/header 规范化和敏感错误脱敏。

## 11. 模型管理验收

- 用户 A 保存的服务、模型、默认模型和凭据状态对用户 B 不可见。
- 连接测试不持久化草稿，不把密钥写入日志。
- 发现预览不会静默覆盖手工参数或自动删除远端缺失模型。
- defaultModelId 不能跨用户、指向归档模型或无效服务。
- revision 冲突不会 last-write-wins。
- 运行中的 Step 在配置保存后仍使用原 Snapshot；下一 Step 才解析新 revision。
- 历史请求在 Model 归档后仍能显示服务名、模型名、revision 和 finish reason。
