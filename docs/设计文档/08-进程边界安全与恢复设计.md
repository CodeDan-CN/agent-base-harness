# 进程边界、安全与恢复设计

## 1. 进程职责

| 运行位置       | 职责                                                              | 禁止事项                                     |
| -------------- | ----------------------------------------------------------------- | -------------------------------------------- |
| Renderer       | React UI、临时草稿、Snapshot/Projection 展示                      | Node、SQLite、Credential、任意文件和原始 IPC |
| Preload        | 固定 Bridge、Schema 边界、订阅清理                                | 业务状态、Agent Loop、原始 ipcRenderer 暴露  |
| Electron Main  | BrowserWindow、活动用户、sender 校验、文件选择、Worker 监护与路由 | 长模型流、Tool Scheduler、业务 Repository    |
| Runtime Worker | 应用服务、Runtime、SQLite、Provider/Tool Adapter、Projection      | 窗口 DOM、未受控 UI 操作                     |

外部模型、工具和操作系统资源必须通过 Worker Adapter；Renderer 不直接调用 Provider 或 Skill。

## 2. BrowserWindow 基线

- `nodeIntegration: false`
- `contextIsolation: true`
- Renderer sandbox 默认开启。
- 仅加载应用自身受信资源。
- CSP 禁止任意 inline script、远程 script 和不必要 connect source。
- 阻止不受控导航、新窗口、下载和外部协议。
- `webSecurity` 不关闭。
- DevTools 和 source map 发布策略按构建环境区分。

任何关闭 sandbox 或增加 Node 权限的需求必须有独立 ADR 和威胁分析。

## 3. Preload 安全桥

Preload 只通过 `contextBridge.exposeInMainWorld` 暴露 `AgentClientApi`。每个函数：

1. 接收固定形状参数。
2. 在 Preload 做轻量结构检查。
3. 调用固定 IPC channel。
4. 在 Main 再执行权威 Schema、sender 和 User Context 校验。
5. 校验响应后返回 Renderer。

Renderer 传来的函数、Prototype 对象、ArrayBuffer 超限数据和不可序列化值全部拒绝。

## 4. 文件选择与受管目录

### 4.1 文件选择

- 只有 Main 调用系统选择器。
- Main 返回一次性 SelectedFileToken，不返回绝对路径。
- token 绑定 userId、windowId、purpose、原始文件元数据和过期时间。
- Worker 通过 Main 受控解析 token，或 Main 将文件复制到受管 staging 后只传 staging handle。

### 4.2 目录

```text
app-data/
  database/
  attachments/<userId>/
  skills/packages/sha256/<digest>/
  staging/<random-token>/
  logs/
  cache/
```

- 所有路径由应用组合，不使用 Renderer 输入拼接。
- 解析后验证 canonical path 仍在对应根目录。
- 受管 Skill package 只读；staging 默认不可执行。
- 日志和 cache 可轮转/重建，数据库和受管文件需迁移保护。

## 5. Credential 边界

- Renderer 只提交新 secret，不读取已保存 secret。
- Main/Worker 中只有 Credential Service 可以访问 OS Credential Store。
- Runtime Adapter 使用短生命周期 secret value/handle，调用结束后释放引用。
- Event、SQLite JSON、日志、诊断和错误 details 不包含明文。
- 命名空间包含 userId 和具体 ModelService/SkillInstallation。
- 不允许“当前用户没有配置时尝试另一用户凭据”的 fallback。

## 6. Runtime Worker 生命周期

### 6.1 启动

```text
Main 创建 Worker
→ Worker 打开日志
→ 打开 SQLite 并验证 PRAGMA
→ 执行/验证 migration
→ 确保两个 LocalUser 与 revision 行存在
→ 清理 staging 并核验受管包
→ 修复开放 Session
→ 重建必要 Projection/checkpoint
→ 发布 runtime.ready(generation)
→ Main 允许业务 Bridge 请求
```

ready 前业务请求返回 `RUNTIME_NOT_READY`，不能在 Main 中临时处理业务绕过 Worker。

### 6.2 正常关闭

1. Main 停止接纳新的变更 Command。
2. Worker 对活动 Turn 请求受控 Cancel 或按产品设置等待短 grace period。
3. 提交已确定的终止事实和 Projection checkpoint。
4. 释放 Session lease、数据库和日志资源。
5. 超时后强制终止；下次启动按崩溃恢复处理。

UI 必须区分“正在退出”“取消已请求”和“已安全停止”。

### 6.3 异常退出

Main：

- 记录 generation、exit code 和最后 heartbeat。
- 采用有界 backoff 重启，防止 crash loop。
- 向 Renderer 发布 runtime.restarting。
- 超过阈值进入诊断状态，不无限重启。

新 Worker：

- 不继承旧进程内存状态。
- 从 SQLite 与受管目录恢复。
- generation 递增，使旧响应/订阅失效。
- ready 后要求 Renderer 重新获取 Snapshot。

## 7. Session 崩溃修复

按 `(userId, sessionId)` 执行：

1. 回放 Event 与 Inbox。
2. 检查 Session lease；过期 lease 失效。
3. 开放 Turn 追加 `turn.ended(reason=interrupted)`。
4. 对应 Exchange 追加 `conversation-exchange.completed(status=interrupted)`。
5. 开放 Step 追加确定的 error/ended 修复事实；具体事件顺序在 Event Contract Fixture 中固定。
6. 已 claim 但未形成 `user.message` 的输入，根据 claim 关联恢复为 next-turn 或明确标记失败，不能丢失。
7. 有 Tool Call 无 Tool Result：
   - replaySafe 且有幂等键：可以在独立恢复策略中核验后重试。
   - 其他情况：写 unknown_side_effect 结果，禁止自动重放。
8. 重建 Projection 并继续合法 next-turn Queue。

恢复追加新事件，不修改历史行。

## 8. 配置与 Skill 修复

启动检查：

- defaultModelId 指向无效/跨用户 Model：清空或标记配置错误并记录诊断，不自动选择替代模型。
- Credential ref 不存在：标记 credential missing，相关服务/Skill 不可用于新 Step。
- enabled Skill 的包缺失或 digest 不符：标记 failed 并从 Registry 排除。
- staging 超过 TTL：清理。
- orphan package：经过保留期且无 lease/installation 后清理。
- uninstalling 且无 lease：继续完成删除。
- config revision 与行状态不一致：通过迁移/完整性修复事务处理，不能只刷新缓存掩盖。

## 9. 双用户后台运行

- 活动用户只影响 UI Query/Subscription，不改变后台 Driver 所属 userId。
- Worker Driver key 是 `userId:sessionId`。
- 每次 Repository、Provider/Skill resolve 和 Event append 使用 Driver 固定 User Context。
- 用户切换不修改已接纳 Command 的 userId。
- Main 丢弃 generation 或 userId 不匹配的迟到响应，不转发给当前 Renderer 状态树。

## 10. Tool 与 Skill 安全

- Tool Registry fail closed；未知 Tool、Schema 错误、权限不足和冲突都拒绝执行。
- 工具修改外部资源默认 exclusive 且 non-replay-safe。
- 网络、文件和进程能力通过 Adapter 受控，不把 Node 全能力直接交给 Skill。
- Tool Args/Result 有大小和 Schema 边界；大结果由工具分页，不由 Runtime 事后裁剪。
- Skill 包安装时静态检查不等于第三方代码沙箱。V1 对未知本地 Skill 必须显示信任提示；实际执行隔离方案需阶段 1 Spike/ADR 验证。
- 用户审批不能授权超过 Manifest 声明或应用允许上限的能力。

## 11. 日志与诊断

结构化关联字段：

```text
userId, sessionId, turnId, stepId, modelRequestId,
toolCallId, requestId, workerGeneration, modelRevision, skillRevision
```

日志规则：

- 默认不记录消息全文、Prompt、Tool Result 全文或 secret。
- URL 移除 query secret；header allowlist 输出。
- 错误栈仅本地诊断使用，UI 返回稳定错误。
- 诊断导出明确选择用户；默认不合并两个用户的正文。
- 安全事件记录跨用户尝试、文件 token 滥用、digest 不符和 IPC sender 拒绝。

## 12. 威胁与控制

| 威胁                      | 控制                                                    |
| ------------------------- | ------------------------------------------------------- |
| Renderer XSS 获取本地能力 | sandbox、contextIsolation、白名单 Bridge、CSP           |
| 伪造 userId               | Main 维护活动用户并注入 Trusted Context                 |
| 任意文件读取              | 系统选择器、一次性 token、受管路径和 canonical check    |
| Skill zip slip/压缩炸弹   | 暂存、安全解压、大小/数量/路径限制                      |
| Skill 静默提权            | Manifest 权限、用户确认、运行时二次校验                 |
| API Key 泄漏              | OS Credential、不可回读、日志脱敏、用户命名空间         |
| 崩溃重复副作用            | replaySafe/idempotency、unknown_side_effect、人工核验   |
| 旧订阅污染新用户          | userId/generation/cursor 校验和主动退订                 |
| SQLite 跨用户关联         | NOT NULL user_id、复合外键、作用域 Repository、负向测试 |

## 13. 恢复验收

- 在模型流、并行工具、Interaction 等待和配置保存各时点终止 Worker，重启后事实一致。
- 未完成 Turn 统一变成 interrupted，不显示 completed。
- Queue 不丢失，已取消 next-step 不复活。
- non-replay-safe Tool 不自动重放。
- Renderer 刷新和 Worker generation 改变后 Snapshot 能重建。
- 用户 A 崩溃恢复事件不会进入用户 B 当前视图。
- Skill 包损坏、Credential 丢失和默认模型无效均 fail closed，并提供可诊断状态。
