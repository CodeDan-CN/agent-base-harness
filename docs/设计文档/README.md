# Agent Client 初始设计草案

> 本目录是总体方案形成过程中的早期分析素材，不代表独立“阶段 0”，不要求在开发前一次性阅读或全部评审，也不直接作为实现依据。每个开发阶段开始前，应重新输出该阶段完整的技术落地方案，并只吸收本目录中经重新核对后仍然有效的内容。

## 1. 目的

本目录保存领域、数据、事件、IPC、模型、Skill、安全和测试方面的初始分析，供后续编写阶段技术落地方案时按需参考。

目录中的 TypeScript、SQL、JSON 和流程片段均为草案或伪代码，不是已冻结 Contract。正式类型、Schema、迁移和实现以对应阶段评审通过的技术落地方案为准。

## 2. 文档关系与优先级

1. `../Agent Client完整技术解决方案.md`：定义产品边界、总体架构、阶段和主要业务流程。
2. `../单Agent低上下文Runtime打造设计.md`：定义 Runtime 语义、不变量和验收标准。
3. 当前阶段技术落地方案：定义该阶段正式实施范围、详细架构和验收 Contract。
4. 本目录：提供早期分析素材，不具备独立决策优先级。
5. `../../AGENT.md`：定义项目长期约束、目录和协作规范。

发现冲突时不得由实现人员自行选择。应先确认并修改总体方案，再写入当前阶段技术落地方案；没有被阶段方案采纳的草案内容不得约束实现。

## 4. 已确认的 V1 基线

- 产品是 Electron 桌面 Client，使用 React、Vite 和 TypeScript strict。
- Electron Main 管理窗口、活动用户和 Runtime Worker；Renderer 无 Node 权限。
- Client 内置两个稳定本地用户，不提供登录、创建或删除用户。
- 两个用户共享一个 SQLite 文件和同一套表，用户私有数据强制使用 `user_id` 隔离。
- Session Event Log 是 Runtime 运行事实来源；模型与 Skill 配置表是用户配置事实来源。
- 单 Session 同时只有一个 Driver；同 Session 串行，不同 Session 可以并行。
- 一个 Step 对应一次模型请求；同一模型响应的多个 Tool Call 收敛后只进入一个后续 Step。
- Tool Result 完整持久化，并与当前 Turn 模型 Surface 使用同一份内容。
- 模型、Skill、凭据引用、历史和 Registry 均按用户隔离。
- 模型与 Skill 变更通过用户配置 revision 和不可变 Step 快照生效。
- Skill 基础格式兼容通用 Agent Skills，以 `SKILL.md` 为入口，可包含 `scripts/`、`references/` 和 `assets/`；来源接入顺序在对应阶段方案确认。
- `reference_ui/` 只提供视觉、比例和交互入口参考，不能作为业务事实或 Runtime Mock 实现。

## 5. 阶段技术落地方案要求

每个阶段开始前只编写并评审该阶段的一份完整技术落地方案，至少包含：

- 阶段背景、目标、范围和明确不做事项。
- 技术架构图及组件职责。
- 模块、数据、接口和关键流程设计。
- 用户隔离、进程边界、权限和恢复设计。
- 测试策略、交付物、验收标准和主要风险。
- 当前阶段必须确认的技术选型与 ADR。

阶段方案评审通过后即可进入该阶段开发，不需要等待其他阶段的详细设计。阶段实施中产生的长期架构变化必须同步回总体技术方案。

## 6. 当前仍需确认的实现选型

这些选择不改变领域语义，但必须在各自对应阶段的相关代码开始前形成 ADR 或写入阶段技术落地方案：

- 首发操作系统范围以及签名、公证和更新渠道。
- SQLite 驱动与迁移执行器。
- OS Credential Store 跨平台库。
- Runtime Worker 的构建、热重载和原生依赖打包方式。
- Skill 来源接入顺序、目录复制/引用策略和宿主机脚本执行确认粒度。
- UUID/ULID 等 ID 生成实现和统一时间库。

未确认实现库时，正式领域接口不得依赖某个候选库的私有类型。
