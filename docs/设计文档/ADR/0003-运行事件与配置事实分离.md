# ADR-0003：运行事件与配置事实分离

- 状态：Accepted
- 日期：2026-08-18

## 背景

Agent 运行需要可回放、审计和恢复；模型与 Skill 设置需要跨 Session 编辑、启停和直接查询。把两者全部放入 Session Event 会造成错误归属，把运行事实改成 CRUD 又会破坏恢复。

## 决策

- Session Event Log 是 Agent 运行事实来源，只追加。
- Model/Skill/Runtime 配置表是用户配置事实来源，使用 expectedRevision CRUD。
- Runtime 每个 Step 解析不可变 ExecutionConfigSnapshot。
- Session Event 记录 Snapshot ID、revision 与非敏感摘要，不复制 secret。
- UI 分别消费 Session Snapshot/Projection 和 Configuration Snapshot/revision。

## 理由

- 各自采用适合生命周期的持久化方式。
- 历史执行可审计，同时设置管理简单明确。
- 配置变化只在安全边界生效，避免执行漂移。

## 影响

- 需要两套明确但不重叠的 cursor：Session seq 与 configuration revision。
- Projection Service 不能把配置表伪装成 Session Event Projection。
- 测试必须验证运行回放和配置 Snapshot 各自确定性。

## 未采用

- 所有设置写入某个 Session Event。
- Runtime 执行中随时查询最新配置。
- 把 UI 本地设置当作事实来源。
