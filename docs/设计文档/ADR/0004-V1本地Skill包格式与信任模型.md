# ADR-0004：V1 自定义本地 Skill 包格式提案（已否决）

- 状态：Rejected
- 日期：2026-08-18

## 背景

参考 UI 提供本地 Skill 安装入口，但其 zip/tar/json 文案只是展示 Mock。正式实现需要一个可静态检查、可原子发布并能明确权限的最小格式。

后续评估发现，ModelScope、ClawHub 等现有生态已经普遍采用通用 Agent Skills 目录：以 `SKILL.md` 为必需入口，并允许 `scripts/`、`references/` 和 `assets/`。如果 V1 强制增加自定义 `skill.json` 和 Tool Manifest，会降低现有 Skill 的直接兼容性并扩大产品实现范围。

## 被否决的提议

- V1 只接受单个 `.zip` 本地包。
- 包根目录必须包含 `skill.json` 和 `SKILL.md`。
- Manifest 声明工具、JSON Schema、入口、权限、secret 和兼容版本。
- 安装期间不执行任何包代码或网络下载。
- 包以规范化内容 SHA-256 寻址并只读发布。
- V1 不建立发布者签名信任链；所有第三方本地包显示“本地未签名”并要求用户明确确认。摘要只保证安装后完整性，不证明作者可信。
- 在线市场、远程更新和受信发布者体系以后续 ADR 设计。

## 理由

- 自定义格式不能直接复用大量现有 Agent Skills。
- 普通 Skill 的主体是按需加载的指令和资源，不应默认等同于动态注册原生 Tool Plugin。
- Skill 脚本可以通过 Runtime 已有的通用命令能力交给宿主机 Node/Python/Shell 执行，不需要先设计专用 Tool Manifest 和 Skill Runner。
- 当前阶段没有必要建设自动依赖安装、发布者签名链和通用插件平台。

## 影响

- 总体方案改为兼容通用 Agent Skills 目录，不强制 `skill.json`。
- Skill 可以携带脚本，但脚本以宿主机当前操作系统用户权限运行；该方案不是安全沙箱。
- 客户端负责来源提示、目录校验、环境检测、首次执行确认、超时/取消、输出采集、环境变量收敛和审计，不自动安装解释器或第三方依赖。
- ModelScope、ClawHub 和本地目录的具体接入顺序、复制/引用策略在 Skill 所属开发阶段的完整技术落地方案中确定。

## 替代方案

- 通用 Skill 目录的本地复制、外部目录引用以及市场下载缓存都是后续可选的来源适配方式，不再通过自定义 Manifest 区分能力。
- 要求所有 Skill 签名：当前没有可信发布和密钥分发体系，暂不采用。
- 为每个 Skill 创建独立虚拟环境或容器：超出当前范围，暂不采用。
