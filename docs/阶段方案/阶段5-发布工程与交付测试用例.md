## 1. 测试目的

验证 macOS 正式产物可以从冻结源码安全、可重复地构建，完成签名、公证、安装、升级、恢复、回滚和卸载，并证明发布包、CI、备份和诊断不包含密钥或用户数据。

## 2. 测试对象与环境

| 对象          | 环境                                                               |
| ------------- | ------------------------------------------------------------------ |
| arm64 DMG/ZIP | Apple Silicon 干净用户、最低/当前支持 macOS                        |
| x64 DMG/ZIP   | Intel Mac 或批准的真实 x64 测试机                                  |
| 签名/公证     | 正式 Developer ID 与 Apple Notary Service                          |
| 升级          | 阶段 1/2/3/4/4.5/4.5.5 数据形状和上一候选版本                      |
| 回滚          | DB 兼容/不兼容两类路径                                             |
| CI            | 受保护发布 runner、无 secret 的普通 PR runner                      |
| 数据          | 合成数据库、附件、Skill、MCP 配置/Tool 审核、外部 MCP 临时数据和 Keychain 测试 namespace |

## 3. 进入与退出条件

### 3.1 进入条件

- 阶段 1～4.5.5 功能基线、数据升级和定向回归通过，已具备冻结候选版本的条件。
- 正式版本、build number、最低 macOS、DB 兼容范围已确认。
- 签名/公证账号、费用、证书轮换和应急联系人就绪。
- 安装/升级/回滚测试设备可重置到干净状态。

### 3.2 退出条件

- 所有 P0/P1 通过，无 Blocker/Critical。
- 两种架构至少各完成一次干净安装、启动、升级和卸载验证。
- 签名、公证、staple、Gatekeeper、hash 和 manifest 全部一致。
- 升级失败和 DB 回滚演练成功。
- 发布文档、检查表和双人批准完整。

## 10. 安全、隐私与供应链用例

- 扫描 DMG、ZIP、asar、unpacked native module、manifest、SBOM、日志和 CI artifact 的 secret/用户数据哨兵。
- 验证 appId、Team ID、签名 identity、最低 macOS、entitlements 和权限描述。
- 验证下载产物 SHA-256 与 `checksums.txt`、release manifest 一致。
- 验证公开产物不可原地替换；相同版本 hash 变化触发阻断。
- 验证依赖锁、许可证、已知漏洞处置和 Electron/Chromium 安全版本。
- 验证诊断包需用户触发，默认无消息/Prompt/Tool Result/Credential/完整路径。
- 验证升级备份仅本地当前用户可读，不自动上传。

## 12. 发布流水线与批准用例

- 错误 tag/version、脏 lockfile、测试失败、签名失败、公证失败、Smoke 失败均阻断。
- 只有受保护 release actor 可触发正式签名和发布。
- 人工批准前产物不可进入 stable 渠道。
- 发布记录包含两位批准人、测试报告、公证 ID、hash、已知问题和回滚点。
- 发布后公开下载重新验证 hash、签名和 Gatekeeper。
- 撤回演练能停止新分发、保留证据并发布明确说明，不覆盖同版本文件。

## 13. 最终全量回归

最终签名、公证后的 `.app` 必须运行而非只测试签名前 build：

1. 阶段 1 基础 Worker/Bridge/SQLite 回归。
2. 阶段 2 Runtime 固定 Fixture 与双用户隔离。
3. 阶段 3 Client 核心 E2E、视觉和 Renderer 安全。
4. 阶段 4 模型目录、供应商预制、上下文压缩、迁移和定向集成回归。
5. 阶段 4.5 MCP Tool Bridge、动态 Tool、Credential、长期记忆和双用户隔离回归。
6. 阶段 4.5.5 权限预设、统一执行审批、OS 沙箱、MCP 加入与调用策略、崩溃恢复和审计回归。
7. 阶段 5 安装、升级、回滚、卸载、签名/公证和产物扫描。

## 14. Go/No-Go 检查

No-Go 条件：

- 任意 P0/P1 失败或未关闭 Blocker/Critical。
- arm64/x64 任一正式承诺产物未通过 Gatekeeper。
- 备份、升级失败恢复或 DB 回滚未通过。
- 产物/CI/诊断出现 secret 或用户数据。
- Manifest/hash 与公开文件不一致。
- 用户指南、隐私、许可证、已知问题或回滚预案缺失。

所有条件通过后，由发布负责人和技术负责人签署 Go。
