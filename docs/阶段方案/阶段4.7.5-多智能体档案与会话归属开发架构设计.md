- 状态：实施中；核心 Agent/Session/委派/MCP 作用域闭环已落地，仍需补齐生产级恢复、容量等待和完整 UI 验收后才能标记 ready。

- 目标版本：server 4.7.5、Gateway 协议 v2、SQLite migration v15；实施前核验编号未被占用，不覆盖已发布 migration。

## 1. 已确认的模型与范围

服务端权威归属为 User → AgentProfile → Session。所有 Agent 同等，既可以直接问答，也可以被获准的其他 Agent 调用。Dylan 是每用户注册时自动创建的默认档案，不是中央路由器；调用方/受派方仅是一次执行的相对关系，AgentProfile 没有固定主次类型。

用户直接打开金融研究员时，它作为根 Session 执行；Dylan 调用金融研究员时，建立归属金融研究员的独立委派 Session。两种入口使用同一个金融 Agent 档案和自己的记忆。

4.7.5 包含档案、会话归属、可调用关系、受限进程内委派、Agent 浅层 MD、单定义 Memory MCP 多作用域实例管理。继续复用 Turn/Step/Inbox/Context/Driver，不要求普通问答先委派，也不增加独立 Decider 或答案生成器。

本阶段不包含跨用户协作、团队编排器、Agent 市场、外部 Codex/Claude 执行后端、全量历史 fork、任意外部工作区、自研多租户 Memory MCP、Agent 硬删除、Skill 自动依赖环境平台。

## 2. 职责边界

| 层                    | 职责                                                                      |
| --------------------- | ------------------------------------------------------------------------- |
| Renderer              | 首页 Agent 展示清单、会话、设置内创建与管理、执行过程；草稿和窗口选中状态 |
| Electron Main/Preload | 安全桥、文件选择和窗口等 OS 能力                                          |
| Client SDK            | 命令、查询、订阅、重连和公开 DTO                                          |
| Gateway               | 认证、Schema、请求上下文、HTTP/SSE；通过 Application 门面访问业务         |
| Application/Runtime   | Agent/Session 规则、能力授权、Step 快照、委派和任务生命周期               |
| 服务 Host             | 装配唯一 MCP 实例管理器、能力目录、共享解释器及基础设施                   |
| Infrastructure        | SQLite、Credential、文件、进程、MCP transport、受管路径                   |
| Memory MCP            | 深层记忆正文、知识图谱、检索和存储语义                                    |

Host 指独立服务宿主，不是 Electron Main。Renderer/Main 不持有数据库、MCP 连接或 Runtime 任务，Gateway 不直接调用 Repository。客户端退出不取消任务。核心 SQLite 保存配置与运行事实，不增长期记忆正文/实体/向量表；浅层 MD 与深层 MCP 分别持有正文。

agent_home_items 属于 Application 层的用户导航配置，不是 Runtime 授权或执行事实。Runtime 只依据可信 userId、agentId、AgentProfile 与能力绑定运行；Agent 是否出现在首页不影响其被直接指定、被其他 Agent 调用或继续持有历史 Session。Renderer 只消费 Gateway 返回的首页投影，不能用本地数组代替该关系。

## 3. 产品交互

左栏顶部保留“新对话”和“创建智能体”；“创建智能体”只导航到“设置 → 智能体”管理页，不在首页弹表单、不直接新增档案。下方标题为“智能体”，标题旁提供“＋”添加入口；首页只平铺用户已加入展示清单的 Agent，各自会话二级展示，取消会话搜索，并可按日期分组、独立折叠。

- 顶部新对话在当前选中 Agent 下创建；Agent 行新对话快捷操作显式传该 Agent ID。
- 点击 Agent 名称进入其最近普通会话，没有则显示其空白首页；点击会话同步选中所属 Agent。
- 智能体档案只在设置中创建和管理。设置页提供档案列表以及独立创建流程，依次配置基本信息、模型与权限、Skills/MCP、可调用智能体和记忆；保存后进入该档案的管理详情，但不自动加入首页、不创建 Session、不启动 MCP。
- 首页智能体标题旁的“＋”打开已有档案选择器，只列出当前用户处于 active 且尚未加入首页的 Agent。选中后把同一个 AgentProfile 加入首页展示清单，不克隆档案、能力、记忆或会话。
- “从首页移除”只删除展示关系，保留 AgentProfile、会话、授权、记忆及受派能力；当前项被移除时切换到首个仍展示的 Agent，清单为空则显示添加智能体空态并禁用无明确归属的顶部新对话。
- 新用户 Dylan 默认获得现有基础工具、内置 skill-creator、builtin-memory 私有绑定。无额外专业 Agent、可调用关系或共享记忆授权。
- 新用户的 Dylan 在注册事务中同时加入首页展示清单；以后在设置中创建的自定义 Agent 默认不加入。
- 自定义 Agent 默认继承用户模型及受限权限默认值，具有基础工具和空的私有记忆；不自动获得用户额外安装的能力、协作 Agent 或共享记忆。内置 Skill 启用项由创建默认配置显式返回。
- Dylan 可改名、修改配置。默认身份由记录确定；先设置另一个默认 Agent 才能归档当前默认项，最后一个活动 Agent 不可归档。
- 归档保留会话和记忆，拒绝新 Turn/委派；已接纳 Turn 按原权限上限收尾。归档提示当前活动任务。
- 委派 Session 从调用轨迹查看，不混入普通会话列表；用户仍可为目标 Agent 单独新建普通会话。
- 执行过程只展示当前 direct Turn 的一层受派调用，按发起顺序标明 A→B、A→C、各自状态和报告；A 把 B 报告用于 C 时，C 的新任务正文留在 A→C 工具事件中，不绘制或暗示 B→C。
- 选中和折叠状态属于每窗口偏好；服务无全局 activeAgentId。无效选择优先回到仍在首页的默认 Agent，否则选择首个首页项；清单为空进入添加空态。登录用户身份始终单独展示。

## 4. 领域与数据库

### 4.1 Agent 与 Session

AgentProfile 字段：id、userId、name、description、avatarKey、instructions、defaultModelId（空值继承用户默认）、permissionPreset、status(active/archived)、isDefault、revision、createdAt、updatedAt。

同用户名称可重复，ID 定位。每用户恰好一个活动默认 Agent，由事务和部分唯一索引保证；defaultAgentId 从 isDefault 派生，不再同时维护 users.default_agent_id。改名不会改变记忆目录。

Session 新增不可变 agentId、origin(direct/delegated)、parentSessionId（可空）。直接会话 parent 为空；委派会话归属目标 Agent，parent 必须指向发起调用的直接 Session。第一版委派是单层星型结构，不存储、不计算委派深度。单个 Session 仍只有一个 Driver；不提供移动会话归属接口。

### 4.2 表与约束

| 表                      | 主键/核心字段                                                                                                       | 约束                                                                                                        |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| agent_profiles          | (user_id,id)，4.1 档案字段                                                                                          | 用户 FK，默认模型同用户 FK；活动默认项部分唯一索引                                                          |
| agent_home_items        | (user_id,agent_id)，sort_order、created_at                                                                          | Agent 同用户复合 FK；同用户 sort_order 唯一；触发器只允许 active Agent                                      |
| agent_skill_bindings    | (user_id,agent_id,skill_id)，enabled、timestamps                                                                    | 两端同用户复合 FK                                                                                           |
| agent_mcp_bindings      | (user_id,agent_id,server_id,access_scope)，enabled、timestamps                                                      | access_scope=user/agent；两端同用户 FK                                                                      |
| agent_delegate_bindings | (user_id,caller_agent_id,callee_agent_id)，enabled、timestamps                                                      | 同用户 FK；禁止 self binding                                                                                |
| agent_delegations       | (user_id,id)，调用 Session/Turn/toolCall、受派 Session、targetAgentId、status、deadline、resultEventRef、timestamps | 两个 Session 同用户 FK；(user_id,parent_tool_call_id) 唯一                                                  |
| sessions                | 增加 4.1 归属与调用字段                                                                                             | Agent/parent 同用户 FK；CHECK 保证 origin/parent 空值组合，触发器保证 delegated 的 parent 是 direct Session |
| mcp_servers             | 增加 default_instance_scope、allowed_instance_scopes                                                                | 普通默认只允许 user；builtin-memory 允许 agent/user，默认 agent                                             |
| user_config_revisions   | 新增 agent_revision                                                                                                 | Agent CRUD、首页展示关系/排序、默认项和三类 binding 变化递增                                                |

导航索引至少包含 agent_home_items(user_id,sort_order) 与 sessions(user_id,agent_id,origin,status,updated_at)。档案创建与首页添加是两个独立命令和事务；CRUD 使用 expectedRevision，冲突整笔失败。归档 Agent 时同时移除首页展示关系，授权变更使相关有效能力缓存失效。

Server 定义不绑定固定 agentId。删除旧稿 mcp_server_scopes 中“一条 Server 只属于一个 Agent”的模型。builtin-memory 私有与共享使用同一 serverId，通过 binding.access_scope 表达授权；私有内置绑定默认启用，共享绑定默认关闭。普通 MCP 不向普通设置页暴露 scope 选择。

agent_delegations 保存可恢复调用事实；delegated Session 创建和调用方工具调用的接纳关系事务提交，内存 Promise 不是唯一事实源。状态转换及关联事件事务提交，查询投影可重建。

MCP 连接状态、generation、lastUsed、lease 数量按实例维护；不能用 Server 的单个 connection_status 代表多个实例。PID/lease 属于 Host 内存状态，重启不恢复为有效连接。持久工具目录按 Server/config revision 管理，实例发现的不同 Schema 使用作用域变体，不能覆盖其他实例的目录。

## 5. 基础工具、Skill 与环境共享

read/write/edit/bash 已由 Runtime 第一方工具注册，独立于 Skill/MCP；询问用户、发现/加载、历史检索等也是内置控制工具。所有 Agent 复用工具实现，权限由工作区、沙盒和审批控制，不将四项基础工具做成可卸载 Skill/MCP。

用户拥有安装物与 Credential，Agent 保存引用和启用关系。同用户多个 Agent 使用同一 Skill 时复用安装目录；指令加载及工具暴露属于当前 Session/Turn，不随共享安装物传播。skill_publish 生成的 Skill 默认仅绑定当前 Agent，不自动授权其他 Agent。

有效集为：用户资源可用/授权上限 ∩ Agent binding ∩ 执行权限。MCP 目录可见不要求进程已连接；休眠不等于禁用，连接错误也不能修改用户 enabled 配置。

应用/服务部署共享 Runtime Pack 中一套 Node、一套 Python 和一份 Memory MCP 包。共享的是解释器文件，不是执行进程。Bash/Skill 执行产生临时进程，stdio MCP 按实例产生进程；cwd、HOME/TMP、环境变量、凭据和可写根各按 Session/实例隔离。

Runtime Pack 的固定依赖只读使用，不允许任务修改全局包目录。可变依赖使用独立受管目录；未来可按 Skill 版本共享 venv/node_modules，本阶段不实现自动依赖安装平台。

SkillCatalog、McpCatalog 与 AgentRepository 仍分别持有各自事实源，McpInstanceManager 只负责 MCP 运行资源。模型侧能力发现统一经过 capability_search，不为 Agent 另建 agent_search，也不新增重复目录。

capability_search 输入为外层 Agent 根据当前对话整理的完整、自包含 `userRequest`、可选 `kinds(skill/mcp/agent)` 和有界 `limit`。Runtime 在当前 Step 的 AgentExecutionConfigSnapshot 上先做确定性权限与状态过滤，再复用当前会话已选模型做语义选择；该内部请求不暴露工具，只包含 `userRequest`、最大选择数和候选的 `kind、capabilityId、name、description` 及必要作用域标签。Skill 不暴露 SKILL.md 正文，MCP 不暴露完整 Tool Schema，Agent 不暴露核心指令、绑定、记忆或会话。description 属于不可信候选数据，选择模型必须忽略其中的指令。

Agent 候选必须同时满足同用户、active、有 caller→callee binding、非自身且当前 Session.origin=direct；是否加入首页不参与选择。delegated Session 仍可用 capability_search 发现自己的 Skill/MCP，但候选中不出现 agent，且不暴露 agent_call。候选目录按 kind/name/capabilityId 稳定排序后交给当前模型，由模型进行同义、跨语言和隐含意图匹配；`limit` 仅限制选中数量，不用于在模型选择前截断授权候选。

统一的是发现入口，不是执行语义：Skill 命中后调用 skill_load，MCP 命中后调用 mcp_load，Agent 命中后调用 agent_call。所有 action 再按当前 Step 快照校验 capabilityId/targetAgentId，不能把旧搜索结果当永久授权。

## 6. 三层记忆与唯一 Memory MCP 定义

| 层级       | 存储所有者                                 | 进入上下文与写入                     |
| ---------- | ------------------------------------------ | ------------------------------------ |
| Session    | 现有 Event/Exchange/Summary                | 复用投影与压缩                       |
| Agent 浅层 | 每 (userId,agentId) 一个 memory-profile.md | 复用有界 MD 投影及 read/edit/write   |
| Agent 深层 | builtin-memory 的 agent 作用域数据文件     | 按需 MCP 检索/写入                   |
| User 共享  | 同一 builtin-memory 的 user 作用域数据文件 | 每 Agent 显式开启，新 Agent 默认关闭 |

浅层/深层是 Agent 长期记忆的两种载体，领域仍为 Session/Agent/User 三层。浅层 MD 是事实偏好参考而非系统指令，可按现有预算进入 Prompt；深层正文仅在检索后进入。不会后台自动抽取会话或 Summary 写入 MD/MCP，写入必须有可观测工具事实。

每用户只有一条 builtin-memory Server 定义，全应用分发一份包；不增加 builtin-private-memory / builtin-shared-memory 两条配置：

```text
builtin-memory
  (user_a, agent, dylanId)   → Dylan memory.jsonl
  (user_a, agent, financeId) → 金融研究员 memory.jsonl
  (user_a, user, user_a)     → 可选共享 memory.jsonl
```

当前官方 server-memory 在启动时绑定一个 MEMORY_FILE_PATH，因此不同作用域需要独立运行实例。创建档案时仅准备数据身份，实例按第 7 节启动。同 Agent 的直接/委派 Session 复用相同私有 MD 和深层实例。

模型可看到“本智能体记忆”“用户共享记忆”两个已授权候选句柄；它们对应同一 Server 的不同路由，不是两次安装。公开 tool name/句柄必须区分 scope，不能让同名工具覆盖；scopeId 根据可信执行上下文解析，不由模型填写。

调用其他 Agent 不授予直接访问其记忆库；目标 Agent 可以把任务相关信息放入返回报告，因此“库访问隔离”不承诺内容级防泄漏。共享记忆也不得跨用户复用连接、数据或凭据。

浅层 MD 按 Agent 文件串行写入并校验 read-before-write 版本，多 Session 冲突后重读，禁止静默覆盖。深层写操作在同实例串行；Runtime 不解释实体/向量语义。归档不删除任何记忆。

限制模式下 read/edit/write、bash、历史检索、MCP 路由均校验归属，禁止通过路径遍历、符号链接或宽泛数据根绕过作用域。full-access 的现有宿主文件权限不是 OS 级 Agent 隔离保证，产品不得把应用级路由隔离宣传成强沙盒。

## 7. Host 级 MCP 实例管理器

每个独立服务 Host 装配唯一 McpInstanceManager，由当前 McpManager 演进：

```text
InstanceKey = userId + serverId + scopeType + scopeId
user  → scopeId = userId
agent → scopeId = 当前 Session.agentId
```

普通 MCP 同用户、同一 Server 定义共享连接。相同包若配置/账号/凭据不同，使用不同 serverId，不能按包名合并。builtin-memory 是本阶段唯一默认 Agent 级 MCP；它的共享访问仍使用 user 实例。HTTP MCP 只建立连接，不在本地拉起 Server。

### 7.1 连接生命周期

1. 创建 Agent、加入/移出首页、创建 Session、修改 binding，以及导航/能力查询不启动 MCP。
2. 安装/更新 Server 可显式连接发现工具，完成后释放临时连接；内置 Memory 目录可取自钉住版本的受检发布快照。
3. capability_search 从当前 Step 快照统一检索 Skill/MCP/Agent；搜索 MCP 候选只读持久目录，不唤醒实例，搜索 Agent 也不创建 Session。
4. mcp_load { capabilityId } 确保连接和 Schema 校验，随后暴露当前 Turn 工具。这有意替代旧版“load 只暴露、不连接”语义；load 使用连接/发现预算，不沿用旧 5 秒上限。
5. 同 Key 并发 acquire single-flight，只建立一个进程；connecting 也占容量。工具调用持有 lease，取消收敛/结束后释放。
6. 模型思考期间实例可休眠，已暴露 Schema 保留；下一工具调用重新 acquire，检查 launch/config/schema revision。Schema 变化需重新加载/审核，不能把旧调用悄悄转到新工具。
7. 初始建议空闲 10 分钟回收、每用户最多 5 个常驻本地 stdio 实例，Host 另设总上限。数值可配置并由压测调整。优先回收无 lease 的 LRU；全部忙时进入有超时、可取消的有界等待，不杀活动调用。
8. 同实例工具调用默认串行，跨 Session 也受此锁约束；确认 Provider 并发安全后才可放宽。同一 Memory 数据文件只有一个活动 writer；测试/刷新复用现有实例或等待，不能开第二个写进程。
9. 空闲关闭状态为 suspended，不记故障、不自动重连。真正崩溃按有界退避重连且计入容量；无需求可休眠。结果未知的修改调用不自动重放。
10. 配置更新、禁用和归档阻止新 acquire，已有调用按安全收敛策略结束；新配置启用新 generation，旧 Step 不静默切换凭据。Host 关闭停止接纳、取消等待、收敛调用并释放连接，保留数据文件。

### 7.2 数据、观测与边界

实例数据根由服务校验并编码 ID 后生成：

```text
<appData>/mcp/users/<userId>/user/<serverId>/
<appData>/mcp/users/<userId>/agents/<agentId>/<serverId>/
```

Server 代码/解释器可共享，HOME/TMP/数据可写根独立。兼容旧数据允许服务内受管 legacy path 映射，不能接收模型或 Renderer 的任意根路径。

管理查询区分 Server 定义、Agent binding、实例状态（suspended/connecting/connected/error、generation、activeCalls、lastUsed、configRevision）；状态查询不启动实例，不返回秘密。Manager 管理连接/锁/容量/目录/lease，不存储记忆正文，不管理 Skill 安装。

## 8. Agent 调用闭环

### 8.1 有向授权与独立执行

agent_delegate_bindings 表达有向关系，Dylan → 金融研究员不产生反向权限。可调用候选通过统一 capability_search 发现，返回名称、简介、agent capabilityId 和 agent_call action；服务在搜索与调用两处都过滤同用户活动目标。Runtime 提供 agent_call { targetAgentId, task, allowSharedMemory? }；allowSharedMemory 默认 false，只能收窄目标已有的共享授权，不能授予新权限。parent Session/Turn/身份由当前工具上下文注入。

调用创建独立 delegated Session，agentId 为目标 Agent，使用目标档案、模型、Skill/MCP 和私有记忆。目标有效能力还受调用方冻结的执行权限上限约束；不自动复制调用者历史、凭据、Skill/MCP。目标共享记忆需目标已授权且此次委派允许。

第一版同步等待、独立上下文、有界文本报告和 delegatedSession 引用，不提供任意 inbox 发信、全历史 fork 或后台永久任务。纯文本直接问答无需 agent_call。

第一版采用单层星型委派：只有 direct Session 暴露 agent_call，delegated Session 一律不暴露该工具，即使其 AgentProfile 配置了对其他 Agent 的调用授权。A 调用 B 后，可由 A 读取 B 的有界报告，再显式选取必要内容组成新任务调用 C；运行时形成 A→B、A→C 两条直接关系，不形成隐藏的 B→C 链，也不让 C 自动读取 B 的 Session、轨迹或记忆。A 也可在同一 Turn 内并行调用多个已授权 Agent。

AgentProfile 仍然完全同等：B 在被 A 委派时不能继续委派；用户直接进入 B 的普通会话时，B 又是 direct Session，可按 B 自己的绑定调用其他 Agent。因执行期不存在嵌套委派，不需要深度字段或运行时环路检测；配置上只禁止 self binding，A→B 与 B→A 可以同时存在并分别用于各自的直接会话。

### 8.2 生命周期与保护

- 每个 direct Turn 最多 3 个同时活动委派，另有 Host 上限；全部直接委派共享该 Turn 的步骤、Token 和截止时间预算。数值实施压测调整。
- 调用方等待 delegated Session 时释放模型执行槽，不能持有全局独占工具锁；防止调用方占满容量导致受派任务永远无执行槽。同 Session 仍单 Driver。
- 调用方取消/截止只取消该 Turn 当前发起的直接委派，不影响目标 Agent 的其他会话。切页面和关闭客户端不取消。
- 受派任务的审批及用户问题通过现有 Session 事件呈现来源 Agent；回复只送对应 delegated Session，调用方保持等待。
- 受派任务完成、失败、取消、超限均有持久终态；按 parentToolCallId 幂等提交一次结果。
- 重启沿用 interrupted 修复：读取持久调用关系，清理悬空等待。已完成结果可补提交一次；执行结果未知时中断报告，不自动重跑可能有副作用的子任务。
- 撤销绑定/归档后拒绝新委派；已接纳任务按冻结的执行权限上限收尾，新增授权不扩大该上限。
- 调用方上下文只收到有界报告，受派任务原始轨迹保留在 delegated Session。两边各自记 usage，汇总不重复计数。

## 9. Migration、工作区与浅层记忆

SQL migration 事务内创建表/列、每用户 Dylan 及其 agent_home_items、旧 Session 归属（direct、parent 为空）、原能力绑定及 revision。保留 Session ID、Event ID/payload/seq、version、时间和附件引用；本次本地部署已按要求清空旧会话，4.7.5 新事件统一使用 Runtime event schema v2，不再为旧 schema 事件做回放兼容。Session 表采用重建/分步填充，保留索引与外键。

升级 Dylan 保留旧启用 Skill/MCP。旧用户浅层 MD 内容初始化为 Dylan 私有 MD，源文件保留。旧 builtin-memory 深层数据保留原路径，映射为同一 Server 的 user 作用域，仅 Dylan 初始授权；Dylan 私有深层为空，新 Agent 不自动获准访问旧共享内容。新注册用户默认没有共享授权。

SQL 事务不涵盖文件系统。事务后由可重入初始化器准备 MD/目录并记录完成标识和摘要：源保留、已存在目标校验而不覆盖新内容。失败阻止该 Agent 新 Turn，提供可重试诊断，不回滚已提交 DB 或伪称完成。初始化不启动 MCP。

保留现有工作区 `<appData>/workspaces/<userId>/<sessionId>/` 及历史产物路径；新增 Agent MD 位于 `<appData>/users/<userId>/agents/<agentId>/memory-profile.md`。Prompt 中旧 `../memory-profile.md` 改成当前 Agent 的逻辑资源句柄 `agent-memory://profile`，read/edit/write 解析到可信路径；该句柄不包含可由模型替换的 agentId。bash 不再借用户公共父目录获得其他 Agent 私有 MD。

重启仅幂等修复缺默认项的不变量，不重建改名后的 Dylan、不删除旧文件。记忆清空/导出/Agent 硬删除另作显式操作，不在本阶段 migration 中执行。

### 13.4 SQLite 与仓储实现

`schema.ts` 只在 `STAGE47_MIGRATIONS` 末尾追加 v15，绝不修改 v1～v14 文本。v15 创建第 4.2 节各表和索引、为现有用户插入稳定 Dylan 档案及 agent_home_items、重建 sessions 以加入归属列，并完整重建原索引、触发器和复合外键。迁移脚本必须在临时旧库副本上先验证行数、Event 引用和 `PRAGMA foreign_key_check`，再进入产品测试。

`WorkerApplication` 装配 AgentManagementService 和 AgentNavigationService。前者处理档案、绑定、默认项、文件初始化与 revision；后者只读取首页关系并批量查询每个 Agent 的一页 direct Session，禁止 Renderer 对 N 个 Agent 发 N+1 次 session.list。Gateway 继续只做认证、请求上下文、Schema 和错误映射，不直接调用 AgentRepository。

设置创建和首页添加严格使用两个命令：

```text
设置保存 → agent.create → AgentProfile + 初始 bindings → 返回管理详情
首页“＋” → agent-management.snapshot + agent.navigation → 过滤候选
选择已有项 → agent.home.add(agentId) → 只新增 agent_home_items
```

### 13.6 Runtime 每 Step 执行快照

当前 RuntimeService 仅按 userId 解析默认模型、全部 Skill 和用户级工具；4.7.5 将此逻辑集中到 `AgentConfigResolver.resolve(scope)`，每个 Step 返回不可变 AgentExecutionConfigSnapshot：Agent 指令与 revision、模型及来源、权限上限、有效 Skill、有效 MCP 路由、可调用 Agent、浅层 MD digest/有界正文和资源 revisions。

RuntimeService 的主要改造点如下：

1. `createSession` 校验同用户 active Agent，并把 Agent permissionPreset 复制为 Session 初始值。
2. `runSession/executeTurn` 每 Step 先从 Session 取 AgentExecutionScope，再解析快照；当前 Step 不复用可变管理对象。
3. `resolveModel(userId)` 改为 `resolveModel(snapshot)`；Skill 列表从“用户全部安装项”改为快照有效集。
4. ContextProjector 不再自行猜测用户 MD 路径；调用方传入 Agent 指令和已读取的浅层记忆数据块。
5. promptEpoch 纳入 agentRevision、Skill/MCP revision 与实际内容 digest，不能只做 revision 数字相加。
6. ToolExecutionContext 增加 agentId、sessionOrigin；基础工具通过可信 scope 解析 `agent-memory://profile`。
7. ToolRegistry 的 Turn 暴露键由 `userId + turnId` 改为 `userId + sessionId + turnId + agentId`。read/write/edit/bash 与 capability_search 保持第一方工具；Skill/MCP 工具按 load 结果暴露，agent_call 仅在 direct 且存在可调用 binding 时暴露。
8. delegated Session 的 capability_search 排除 agent 候选且不暴露 agent_call；服务端执行入口仍二次校验 origin，防止伪造旧 Schema 调用。

`AgentConfigResolver` 只读取配置和文件投影，不启动 MCP、不创建 Session、不修改 revision。其输出既用于 Prompt，也用于模型 Tool Schema 和工具执行校验，避免三处各自计算“这个 Agent 能做什么”。

现有 `capability-discovery.ts` 演进为统一 CapabilityDiscoveryService，从同一个不可变快照建立三类轻量候选。它不直接查全库、不绕过 Agent binding，也不拥有 load/call 生命周期。返回 action 只用于告诉模型下一步入口，例如 `{ kind: 'agent', capabilityId, name, description, action: { tool: 'agent_call', targetAgentId } }`；agent_call 仍重新授权，防止搜索后配置已被撤销。

### 13.7 单层委派实现

`agent-call-tool.ts` 只负责 Schema、调用展示和把 ToolExecutionContext 交给 DelegationCoordinator；它不直接操作 Repository。Coordinator 的一次调用顺序固定为：

1. 从调用方 Session 校验 origin=direct、同用户 active 目标、有向 binding、非 self，以及 direct Turn 共享预算。
2. 在一个 SQLite 事务中写入 agent_delegations、创建 delegated Session，并登记 parentSession/Turn/toolCall；重复 parentToolCallId 返回同一接纳结果。
3. 向 delegated Session 投递唯一初始 task，启动现有 RuntimeService Driver，并等待终态；不复制调用方历史。
4. 将 child 的 waiting/approval/终态投影为调用方 Session 的 `agent.delegation.*` 事件，供现有 SSE 和 ExecutionProcess 展示；原始轨迹仍只在 delegated Session。
5. 完成时生成有界报告、resultEventRef 和 delegatedSessionId，幂等提交 agent_delegations 终态，并作为 agent_call 的 Tool Result 返回。

取消按 `parentSessionId + parentTurnId` 查询当前直接受派项并传播 AbortSignal。恢复时 DelegationRepository 扫描非终态记录：已有终态报告则补交一次，执行结果未知则标记 interrupted，不自动重放副作用。

当前 RuntimeService 的 `maxParallelSessions` 在 `runSession` 全程占槽，多个调用方同时等待 Agent 时会造成容量死锁。4.7.5 必须把它重构为 `ExecutionPermitPool`：仅模型请求和需要限制的本地执行持有 permit，进入 agent_call 等待前释放，恢复调用方推理时重新 acquire；Session lease 继续持有以维持单 Driver。不能只提高 maxParallelSessions 掩盖死锁。

### 13.8 MCP 实例池改造

当前 `McpManager.start()` 和用户初始化会连接全部 enabled Server，连接键只有 `userId + serverId`。4.7.5 必须删除这两处 eager refresh：启动只加载持久目录并注册发现入口，显式测试/刷新使用短租约，模型 `mcp_load` 或真正调用工具时才 acquire。

`McpInstanceManager` 的最小接口为：

```ts
interface McpInstanceManager {
  acquire(input: {
    key: McpInstanceKey;
    server: McpServer;
    configRevision: number;
    signal: AbortSignal;
  }): Promise<McpInstanceLease>;
  snapshot(userId: LocalUserId): readonly McpInstanceView[];
  invalidate(userId: LocalUserId, serverId: string): Promise<void>;
  close(): Promise<void>;
}

interface McpInstanceLease {
  client: Client;
  generation: number;
  release(): void;
}
```

Manager 内部以 InstanceKey 保存 connecting Promise、Client、generation、activeCalls、lastUsed、idle timer 和写串行锁。`mcp-instance-paths.ts` 根据可信 scope 生成 cwd/HOME/TMP/MEMORY_FILE_PATH；调用参数中不出现任意文件路径。McpManager 负责从 Agent 快照选择 scope、查工具目录、获取 lease、调用并 finally release，不再自己维护 connections/reconnectTimers。

现有 mcp_servers.connection_status/generation/last_error 列在 v15 可保留作兼容废弃列，但业务不再读取为实例权威状态；管理页实例状态来自 McpInstanceManager.snapshot。McpManager 的 test/refresh 不得绕过实例容量、同文件 writer 和关闭流程另起第二个 Memory 进程。

### 13.9 Agent 浅层记忆文件

将 `ensureUserMemoryProfile/readUserMemoryProfile` 从 `session-workspace.ts` 迁移为兼容入口，新的 `agent-memory-profile.ts` 提供：`pathFor(userId, agentId)`、`ensure`、`readVersioned`、`writeIfVersion`、`initializeFromLegacy`。文件写入使用同目录临时文件、fsync 后原子 rename；版本可用内容 digest，不依赖进程内计数。

受限文件工具不接受真实 Agent MD 路径，只接受 `agent-memory://profile`；解析器从 ToolExecutionContext 得到 userId/agentId，再执行 realpath、符号链接和受管根检查。bash 的 Session 工作区不把 `<appData>/users/<userId>/agents/` 设为可见父目录。

### 13.10 Renderer 状态与组件调用

App.tsx 增加 `agentNavigation`、`activeAgentId` 和 `activeSessionId`，约束为“Session 选择必须属于当前 Agent”。登录/重连先获取 Bootstrap 和 agent.navigation，再按“窗口保存项 → 首页默认 Agent → 首项 → 空态”确定选择。Agent 切换只取消旧 SSE 订阅和加载新快照，不发送 Runtime cancel。

Sidebar 不再接收扁平 sessions，而接收 AgentNavigationItem[]；每项内部只渲染服务返回的最近一页 direct Session。顶部“创建智能体”调用 `openSettings('agents')`，标题“＋”打开 AgentPickerDialog；两者不得复用同一个 onCreate 回调。设置保存成功只刷新 agent-management.snapshot；agent.home.add 成功才刷新首页导航。

设置草稿只存在 AgentCreateFlow 组件，最终提交前不写服务端。多步流程关闭时提示丢弃草稿；保存成功后选中管理详情但不改变 activeAgentId。AgentBindingsEditor 只提交 ID 与 expectedRevision，不把 Credential、Skill 正文或 MCP 环境变量复制进 AgentProfile。

### 13.11 测试文件与实施顺序

测试不集中写成一个 stage475 巨型文件。按边界拆分：Repository/Service/Resolver/InstanceManager/Coordinator 使用 unit；method 联合、Zod、DTO 和错误用 contract；迁移、Runtime、SSE、真实 Memory 子进程使用 integration；跨用户和路径使用 security；用户可见创建/添加/移除/直接问答使用 e2e。

建议提交顺序如下，每一步都保持 typecheck 和既有测试可运行：

1. 领域类型、v15 migration、仓储和迁移回归。
2. Agent 管理/首页服务、契约、Dispatcher、SDK 与 Bootstrap。
3. 设置创建流程、首页选择器和 Agent 两级导航。
4. Session 归属、AgentConfigResolver、Prompt/Skill/基础工具作用域。
5. McpInstanceManager、单 Memory 定义多作用域和零启动改造。
6. DelegationCoordinator、agent_call、执行 permit、取消与恢复。
7. 真实进程、安全、容量、迁移和 Electron/CLI 联合回归。

明确禁止的捷径：在 AgentProfile 中塞完整 Skill/MCP 配置副本；用 Agent 名称作为主键或记忆目录；首页数组只存 Renderer；为每个 Agent 常驻一个 Runtime/Node 进程；让 McpManager 启动时连接所有 Server；让 delegated Session 获得 agent_call；让 Gateway 或 UI 直接访问 Repository。
