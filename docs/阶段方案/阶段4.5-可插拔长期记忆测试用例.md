## 1. 测试目的

本测试文档验证以下阶段新增能力：

1. stdio 与 Streamable HTTP MCP Server 可以按用户配置、连接、发现、调用、动态刷新、重连和释放。
2. 发现到的工具先进入管理目录，只有已审核启用的工具进入下一 Step Snapshot，Schema 变化不会静默替换运行定义。
3. MCP Tool 的稳定命名、权限、取消、结果校验、事件持久化、Surface 投影和上下文预算正确接入现有 Runtime。
4. Memory Provider 与 Runtime、存储实现解耦，默认 `user-memory` Skill 保持渐进加载。
5. 随包文档型 Memory Server 支持短/长读取、整体替换、纠错、忘记、revision 冲突和跨 Session 召回。
6. 长期记忆正文不写入核心 SQLite 内容表，两个用户不发生任何 MCP、Provider、Credential、目录或 UI 串扰。
7. MCP/Memory Tool 与阶段 4 Context/Compaction、Worker 恢复和 Client 管理界面正确接线。

## 2. 测试层级与环境

| 层级 | 主要对象 | 外部依赖 |
| --- | --- | --- |
| Unit | MCP 名称、Schema digest/diff、Memory Schema、阈值、Markdown、错误映射 | 无 |
| MCP Contract | initialize、分页 tools/list、list_changed、tools/call、两种 transport | Fake stdio/HTTP Server |
| Integration | Tool Catalog、Supervisor、Runtime Bridge、Memory Service、SQLite 配置 | 临时 DB/目录、Fake MCP |
| Runtime | Skill 加载、跨 Session、并发写、Compaction | Scripted/Fake LLM |
| Client E2E | 设置、编辑、用户切换、错误和清空 | Electron 测试构建 |
| Live Optional | 真实模型自主加载 Skill、记住和召回 | 用户显式提供模型配置 |

自动化不得依赖用户真实长期记忆目录。所有文件和 MCP 子进程必须使用测试创建的精确临时根，并在用例结束后释放。

## 3. 进入与退出条件

### 3.1 进入条件

- 阶段 4 模型能力、思考配置、Session/Event Summary 和 Surface Compaction 基线通过。
- 当前 Skill Catalog、`skill_load`、Tool Registry、Bridge 和双用户 Scope 测试通过。
- Memory Contract、默认目录和错误码已冻结。

### 3.2 退出条件

- 本文全部 P0 用例通过。
- P1 用例无影响数据正确性、用户隔离和恢复的阻断失败。
- 无残留 MCP 子进程、临时文件、未清理锁和跨测试状态。
- 阶段 1～4 全量默认自动化继续通过。
- 至少完成一次打包前资源路径 Smoke；正式签名产物验证进入阶段 5。

## 9. 文档型 Provider 用例

### 9.1 文档格式和阈值

| ID | 优先级 | 场景 | 预期结果 |
| --- | --- | --- | --- |
| S45-P01 | P0 | MEMORY.md 不存在 | overview 返回 empty，不创建文件 |
| S45-P02 | P0 | 首次 replace | 创建合法 frontmatter、正文、revision 1 和 digest |
| S45-P03 | P0 | 文档不超过 1024 token | overview 返回全文，`requiresRead=false` |
| S45-P04 | P0 | 文档超过 1024 token | overview 只返回摘要/章节，`requiresRead=true` |
| S45-P05 | P0 | 长文档 replace 不提供 summary | 返回 `MEMORY_SUMMARY_REQUIRED`，旧文件不变 |
| S45-P06 | P0 | summary 超过 256 token | 拒绝写入，旧文件不变 |
| S45-P07 | P0 | 文档超过 8192 token | 返回 `MEMORY_DOCUMENT_TOO_LARGE`，不截断写入 |
| S45-P08 | P0 | UTF-8 超过 65536 bytes | 返回硬上限错误 |
| S45-P09 | P1 | 中英文、emoji、CRLF | 规范化后 token/digest 稳定 |
| S45-P10 | P0 | 章节超过 32 个 | overview 章节有界，全文不受静默改写 |

## 18. Go/No-Go 检查

满足以下全部条件才可进入阶段 5：

- 所有 P0 通过。
- stdio 与 Streamable HTTP Tool Bridge 均通过协议和 UI 主链路测试。
- 新工具默认关闭，Schema 变化会失效旧审核，运行中 Step 不发生定义/路由错位。
- 没有 Tool Catalog 半更新、Tool 名覆盖、无限 Schema 注入或无界 MCP 结果进入 Surface。
- 没有长期记忆正文进入核心 SQLite 内容表。
- 没有跨用户 Credential、Catalog、连接、目录、进程、调用、配置或 UI 泄漏。
- 没有丢失更新、无界重连或假成功确认。
- MCP transport、重连 timer 和子进程可在 Worker/应用退出时可靠释放。
- MEMORY.md 原子替换和备份恢复通过故障注入。
- 阶段 1～4 默认自动化无回归。
- 阶段 5 已同步将 MCP 配置/Credential 清单和 Memory Provider 目录纳入打包、用户数据、备份、卸载和诊断策略。
