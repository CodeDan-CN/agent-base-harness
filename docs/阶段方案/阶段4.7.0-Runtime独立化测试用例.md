# 阶段 4.7.0：Runtime 独立化测试用例

- 文档状态：待评审
- 所属阶段：阶段 4.7.0（Runtime 独立化与 CLI/Electron 双端接入）
- 更新日期：2026-09-06
- 对应设计：[阶段 4.7.0 Runtime 独立化设计](阶段4.7.0-Runtime独立化开发架构设计.md)
- 回归基线：阶段 1～4.6.0 已完成测试与当前工作区行为

## 1. 测试目的

证明 Runtime 已从 Electron 生命周期中独立为本地 Node.js 服务，并验证：

1. 不启动 Electron 也能通过 CLI 注册或使用预置账号登录并运行 Agent。
2. CLI 与 Electron 分别使用时连接同一个服务和数据目录。
3. Gateway 与 Runtime 作为同一进程、同一发布物中的代码模块工作。
4. 服务独占 Runtime 任务和 SQLite，客户端退出不终止已接纳任务。
5. 本地注册登录能够把可信用户身份注入 Runtime，不能通过请求参数越权。
6. 客户端稍后进入或断线重连时，能从权威快照和持久事件恢复状态。
7. 现有单 Agent Runtime、权限、模型、MCP、Skill、事件和恢复语义没有退化。

本阶段测试不把多端实时协同作为产品能力。允许 CLI 与 Electron 偶然同时连接，但只验证不会产生双 Runtime、数据损坏或越权；不验证 Presence、共享草稿、操作来源展示、主客户端租约或实时协同界面。

## 2. 测试分级与类型

### 2.1 优先级

| 优先级 | 定义                                                                               |
| ------ | ---------------------------------------------------------------------------------- |
| P0     | Runtime 独立、数据唯一所有权、认证、用户隔离、任务持续和安装可用性；失败阻断 4.7.0 |
| P1     | 主要错误路径、断线恢复、偶然连接重叠和客户端兼容；失败原则上阻断                   |
| P2     | 性能记录、诊断质量和低概率组合；失败需记录并评估                                   |

### 2.2 测试类型

| 类型        | 主要对象                                                          |
| ----------- | ----------------------------------------------------------------- |
| Unit        | 密码摘要、令牌、连接登记、实例锁、CLI 参数和错误映射              |
| Contract    | HTTP 请求/响应、认证头、RuntimeFacade、SSE 事件和错误码           |

| Process     | 启动竞争、客户端退出、服务关闭、异常退出和恢复                    |

| E2E         | 真实 CLI 子进程与 Electron UI 的完整用户路径                      |
| Regression  | 阶段 1～4.6.0 Runtime 和 Client 既有测试                          |

## 3. 测试环境与 Fixture

### 3.1 自动化环境

- macOS arm64 为当前主验证环境；x64 和正式签名由阶段 5 完成。
- 每个测试使用独立临时数据目录、临时日志目录和随机空闲回环端口。
- 使用真实 better-sqlite3；除 Package 用例外，可使用当前开发 Node.js。
- 使用 Scripted Model、Scripted Tool、Fake Credential Store、Fake Clock 和确定性 ID。
- 服务进程测试必须通过真实子进程启动，不以内存函数调用代替全部集成测试。
- Electron E2E 使用真实 Main、Preload、Renderer 和服务产物。

### 3.2 固定 Fixture

| Fixture               | 内容与用途                                                   |
| --------------------- | ------------------------------------------------------------ |
| fresh-local-install   | 空数据目录，启动后自动具备两个内置账号                       |
| existing-two-users    | 当前 Schema 数据库，user-a/user-b 均有会话和配置但无登录凭据 |
| legacy-credentials    | 两个数据域存在旧自定义登录名或密码                           |
| registered-local-user | 通过账号文本输入注册的新用户，具备独立稳定 userId            |
| running-turn          | Scripted Model 被 barrier 阻塞，便于测试客户端退出           |
| pending-approval      | 已持久化待审批工具调用                                       |
| completed-session     | 已完成会话及连续事件序号                                     |
| reconnect-gap         | 客户端断线期间继续追加若干事件                               |
| invalid-origin        | 带浏览器 Origin 的回环请求                                   |
| slow-sse-client       | 建立订阅但暂停读取响应体                                     |
| package-clean-room    | 无 Electron、无仓库源码的干净安装目录                        |

测试密码使用固定哨兵值；测试结束后扫描 SQLite、日志、发现文件、CLI 配置和测试产物，哨兵不得以明文出现。

## 4. 进入与退出条件

### 4.1 进入条件

- 4.7.0 Gateway、RuntimeFacade、Client SDK、CLI 和 Electron 接线已经实现。
- 登录、当前用户和退出的 Schema 已冻结。
- 本地登录凭据 migration 可以在 existing-two-users 副本上执行。
- Scripted Runtime 可以通过正式 RuntimeFacade 注入，不建立测试专用业务旁路。
- 当前阶段 1～4.6.0 自动化基线通过，或已有明确记录的既存失败清单。

### 4.2 退出条件

- 所有 P0、P1 自动化通过；P2 无未评估失败。
- CLI-only 和 Electron 两条真实 E2E 均通过。
- npm 包在 package-clean-room 中安装、启动并完成基础任务。
- 现有 Runtime、用户隔离、权限、MCP、Skill 和 Projection 回归通过。
- 无 Electron 内 Runtime 所有权、客户端数据库直连或同目录双写路径。
- 测试报告记录版本、提交、Node/Electron 版本、平台、命令、结果和已知问题。

## 15. 偶然连接重叠

这些用例只保证安全共存，不把多端实时协同列入产品承诺。

| ID      | 优先级/类型      | 场景                             | 预期结果                                            |
| ------- | ---------------- | -------------------------------- | --------------------------------------------------- |
| S47-O01 | P1 / Integration | CLI 与 Electron 同时连接但不操作 | 两个连接均可用，无第二 Runtime 或数据库连接         |
| S47-O02 | P1 / Integration | 同账号先后提交两个不同输入       | 两个输入按现有 Inbox/Queue 语义接纳，不丢失、不覆盖 |
| S47-O03 | P1 / Integration | 两端重复提交同一幂等输入         | 只产生一个 InboxItem                                |
| S47-O04 | P1 / Integration | 两端偶然解决同一审批             | 只有一个决议成功，另一个得到已解决/冲突结果         |
| S47-O05 | P1 / Integration | 关闭其中一个连接                 | 只清理该连接，另一个连接和 Runtime 状态不受影响     |

不要求验证两端瞬时画面完全一致、共享输入草稿、显示对方在线状态或建立控制权转移。
