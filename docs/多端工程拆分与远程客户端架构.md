# 多端工程拆分与远程客户端架构

本方案按本次产品决策实施，取代早期方案中的单源码包、Electron 自动启动服务及桌面内置 Runtime 交付约定。Runtime 的任务、存储和执行语义沿用既有实现。

## 工程与产物

采用 npm workspaces，保留一个仓库和根 package-lock.json。

| 工程                  | 职责                                                          | 产物                                       |
| --------------------- | ------------------------------------------------------------- | ------------------------------------------ |
| apps/server           | 装配服务并托管 Web；提供服务器管理入口                        | Server npm 包、自包含 Runtime 包           |
| apps/web              | 浏览器入口与平台适配                                          | 静态 HTML/CSS/JS                           |
| apps/desktop          | Electron Main/Preload/Renderer、服务器地址配置                | 纯客户端 .app / DMG                        |
| apps/cli              | 远程命令行客户端、按服务器隔离令牌缓存                        | 独立 CLI npm 包                            |
| apps/mobile           | OLED 手机布局、远程适配与 Android WebView 壳                  | 静态资源 / 开发 APK 构建入口（待真机验收） |
| packages/protocol     | Zod 契约、公共类型、错误码、API 版本与纯投影                  | 内部共享包                                 |
| packages/client-sdk   | 共用 HTTP/SSE、认证、ZIP 上传、产物下载                       | 浏览器兼容 SDK                             |
| packages/app-ui       | Web/Desktop 共享 React 界面，注入 AgentClientApi              | 内部共享包                                 |
| packages/server-core  | Gateway、身份上下文、Application、RuntimeFacade、服务生命周期 | 服务内部包                                 |
| packages/runtime-core | Agent Driver、模型、上下文、Tool、Skill/MCP                   | 服务内部包                                 |
| packages/storage      | SQLite、Migration、Repository                                 | 服务内部包                                 |
| packages/execution    | 工作区、文件、进程、凭据、Provider 适配和执行环境             | 服务内部包                                 |
| packages/test-kit     | 原 tests/fixtures 中的时钟、数据库、Runtime 等 Fixture        | 测试内部包                                 |

内部包使用明确的 workspace 依赖；源码导入沿用可被 TypeScript/esbuild 解析的相对路径，生产入口统一打包。内部包不分别发布。
build-support/server-package 是服务分发模板与暂存目录，不是另一个 Server 实现。dist 为统一构建输出；release 为可分发产物。

## 依赖与数据边界

- Web、Desktop、CLI、app-ui、client-sdk 只依赖客户端侧 workspace 和 protocol。边界脚本检查每条静态导入及声明的 workspace 依赖。
- protocol、client-sdk、app-ui、Web 不允许导入 Node builtin、Electron 或 SQLite。
- UI 通过 configureClient 注入 AgentClientApi；浏览器使用 SDK，Electron 通过固定 Preload API 由 Main 调用 SDK。访问令牌不返回 Electron Renderer。
- Desktop 启动只创建客户端窗口；服务器地址保存在客户端 connection.json，连接失败不会启动本机服务。关闭或切换客户端不停止 Runtime。
- Server 在 macOS、Ubuntu/Linux、Windows 上统一通过 SQLite 的 `credential_secrets` 表保存模型/MCP API Key 明文，不依赖系统钥匙串或独立加密文件。客户端只读取凭据配置状态，旧数据迁移见[凭据存储与迁移](Runtime凭据存储与迁移.md)。
- Server 独占数据库、工作区、模型凭据、Node/Python 和 MCP。客户端选择的 Skill ZIP 上传后安装；服务器产物通过认证下载接口获取。
- CLI 登录缓存按规范化服务器 URL 的 SHA-256 分隔；远程客户端不读服务器 discovery 或 bootstrap 文件。旧本机服务发现保留在 server-core，仅供服务器管理员工具使用。
- 既有 Worker/Bridge 测试支持代码位于 server-core/legacy 和 application。它们不进入生产 Desktop 包。

本次保留 Runtime 与存储/执行适配器之间已有的内部依赖；没有额外拆进程，也没有重写 Agent 调度语义。

客户端会话 ID、提交幂等键及手机原生请求 ID 统一使用 `createClientId`。HTTPS/localhost 优先使用原生 `crypto.randomUUID()`；局域网普通 HTTP 等不提供该方法的环境使用 `crypto.getRandomValues()` 生成 UUID v4，不依赖 `Math.random()` 或时间戳，避免首次发送、确认授权等操作在浏览器内直接失败。

## 模型配置与会话选择

Web/Desktop 共用模型管理页，负责模型服务连接、模型增删和上下文配置。模型列表不再提供用户默认模型单选框、思考模式及思考强度下拉框；用户在聊天输入框的模型选择弹层中切换当前智能体的模型，并按模型支持的能力调整思考程度。保存上下文配置时保留该模型已有的思考设置。

## 会话普通文件上传

Web/Desktop 输入框的附件按钮支持选择多个普通文件，每个最多 20 MB。选择后先创建或取得当前会话，再通过 SDK 的 `POST /v1/sessions/:sessionId/files` 上传原始字节。Gateway 从客户端身份上下文取得 userId，并在读取上传正文前验证会话归属；文件名不允许目录分隔符、路径穿越或控制字符，保存目录不接受符号链接。

文件保存在 Server 的 `workspaces/<userId>/<sessionId>/attachments/file-<随机值>/<原文件名>`，每次上传单独建目录，不覆盖同名文件。响应只返回名称、绝对路径、字节数。Desktop 使用固定 Preload 上传 API，本地登录状态仍保留在 Main；客户端本地路径不会作为服务器可读路径发送。

上传完成后，绝对路径作为带引号的一行文字插入输入框，原有问题保留，用户可编辑再发送。`input.submit`、Inbox、会话事件和模型请求仍使用同一份纯文本；上传文件不会自动触发模型调用，也不把正文或 Base64 展开到上下文。模型根据任务使用现有 read、bash 或已加载的 Skill 按需读取，读取范围及权限仍由既有工具策略决定。PDF、Office 等文件不在上传阶段解析，图片输入本次未开放。

上传期间阻止发送，失败保留问题，批量上传中成功的路径仍插入草稿；新会话创建后的草稿迁移和切换会话后的路径归属保持一致。取消文件选择不创建会话。已上传的文件随会话工作区保留，删掉输入框里的路径不会删除文件；此阶段不新增附件数据库表或自动清理任务。

验证包含真实 Gateway/SDK 上传、同名与二进制保存、归属/大小/路径边界，以及脚本模型先收到路径、调用 read 后才收到正文。`npm run verify:remote` 还验证 Web 新会话、Desktop 已有会话的选择上传、草稿保留和发送失败重试。

## 启动和开发

生产源码部署：npm run build:server 后 npm start。默认 127.0.0.1:4317，Web 与 API 同源。可通过 npm start -- --host 0.0.0.0 --port 4317 开放受控网络访问。

默认 npm run dev 启动一个本地 Runtime、Web Vite（5174）和 Desktop Renderer Vite（5173）及 Electron。
开发 Runtime 默认使用服务端的本机数据目录，macOS 优先沿用已存在的 `~/Library/Application Support/agent-base-harness/database/app.db` 及同目录资源。可用 AGENT_HARNESS_DATA_DIR 覆盖；需要独立开发数据时可显式设为 app-data/development。账号注册在客户端本地完成。
启动器关闭时只停止本次创建的子进程；单独退出已打包 Desktop 不影响任何 Server。

| 命令                             | 行为                                               |
| -------------------------------- | -------------------------------------------------- |
| npm run dev:server / dev:runtime | 单独启动开发 Runtime                               |
| npm run dev:web                  | 浏览器前端开发，代理到 AGENT_HARNESS_SERVER_URL    |
| npm run dev:desktop / dev:client | 只启动 Electron 开发端，连接已运行的 Runtime       |
| npm run build:server             | 构建 Server、管理员 CLI、SDK 及 Web                |
| npm run build:desktop            | 只构建 Main、Preload、Renderer                     |
| npm run pack:desktop             | 生成纯客户端应用目录                               |
| npm run dist                     | 生成当前 macOS 目标的 DMG                          |
| npm run pack:server              | 打包 Server 并执行干净安装、SQLite 和 Web 启动验证 |
| npm run pack:cli                 | 打包不含 Server 的远程 CLI                         |
| npm run pack:runtime:macos       | 沿用 macOS arm64 自包含 Runtime 打包链路           |

AGENT_HARNESS_SERVER_URL 默认 http://127.0.0.1:4317。Web 开发代理和 Desktop/CLI 使用该地址。
Desktop 首屏可填写和保存服务器地址；连接后可切换服务器，随后重新登录。
AGENT_WEB_DEV_PORT 与 AGENT_CLIENT_DEV_PORT 分别控制两个 Vite 端口。

## 客户端用户与 Runtime 数据归属

2026-09-11 产品决定：当前所有本地、远程运行方式统一信任客户端身份。注册、密码校验、登录状态由客户端负责，Runtime 不管理账号、密码或登录令牌。此约定替代此前的 Server 本地账号与远程注册机制。

2026-09-12 本地使用更新：按用户要求，客户端初始化时补建内置 `user-a` 账号（密码 `user-a123`），固定关联旧 `user-a` 数据分区。客户端代码仅保存 bcrypt 摘要，已存在的同名本地账号不会被覆盖。此约定替代旧文档中“不预置账号”的要求；Runtime 身份协议不变。更新 Web 构建时须同步重启旧 Runtime，避免新版客户端身份请求被旧令牌认证拒绝。

- Web 用当前站点 localStorage 保存账号与 bcrypt 密码摘要，sessionStorage 保存当前本地会话引用；Desktop Main 与 CLI 用本机 `local-accounts/` 文件，目录 0700、文件 0600；Mobile 用本机 localStorage 保存账号摘要，登录引用只驻留内存。明文密码和摘要不发送到 Runtime。
- 各客户端账号独立。注册仅接收账号和密码，系统自动生成随机稳定 userId，用于内部数据归属。Web/Desktop/Mobile 的账户与注册界面均不展示用户 ID，不提供手动填写或绑定功能；CLI 注册与账号信息输出同样不提供此入口或展示该标识。
- SDK 的 `registerRemote` 和 `register` 暂留为兼容方法名，实际只创建本地账号；`login/me/logout` 也只操作本地。嵌入方可直接用 `new AgentClient({ baseUrl, clientKind, user: { id, loginName, displayName } })` 或 `setUser` 接入自己的用户信息。
- HTTP/SSE/上传下载统一传 `x-agent-user: encodeURIComponent(JSON.stringify({ id, loginName, displayName }))` 与 `x-agent-client-kind`。身份不放 URL；不再使用用户 Bearer Token。服务只校验请求格式和路径安全，直接信任所声明身份。`id` 为 1–128 个 ASCII 字母、数字、下划线或连字符，首位为字母或数字。
- 首次请求时，Runtime 幂等初始化该 ID 的数据空间、默认 Agent 和配置。已有 ID 的会话、记忆、模型凭据不重建或迁移；资源归属检查继续按传入 ID 执行。用户列表只返回当前分区，不承担账号管理。
- `/v1/auth/*` 返回 410 并提示升级客户端；旧 `--allow-registration/--allow-web-registration` 为无效果的兼容参数。服务启停管理的主机 bootstrap token 独立保留。
- 已有本地账号保留保存的内部标识，继续访问原有会话与配置；旧数据库及凭据行保留。新注册账号分配新的数据空间，不通过账号同名或手动输入标识关联旧数据。
- 服务重启不使客户端本地会话失效；本地登录有效期为 8 小时。退出登录或切换身份会关闭该客户端的事件订阅，不取消已接纳的任务。

当前身份属于客户端声明的数据分区，知道别人的 ID 即可声明为该用户，不提供服务端身份真实性校验。Origin 同源检查、工具权限和文件路径限制仍保留。未来接入用户服务时，在接入边界替换身份来源，不改 Runtime 分区语义。

## 手机首版边界

apps/mobile 已有独立连接页、手机布局、SDK 适配与 Android WebView 壳源码；手机永不内置 Runtime。APK 本地打包 React 界面，通过原生 HTTP/SSE 连接指定服务器，复用现有 TypeScript 协议与投影，不复制一份 Kotlin 业务契约。
保留登录、聊天、会话和必要审批，隐藏管理设置。公网 HTTPS；HTTP 限明确的私有 LAN IPv4。令牌暂只存内存，服务器 URL 可记住。默认 npm start/npm run dev 的行为保持不变，不自动启动手机预览。
npm run dev:mobile 只启动电脑浏览器的手机 UI 开发预览；npm run build:mobile 构建 APK 内资源；npm run pack:mobile 需要独立配置 Android SDK 35、JDK 17、Gradle 8.9。
当前手机 UI/真实 Runtime 流程和独立 Java 网络边界测试已验证，Android Activity/网络桥编译和真机仍待验收；没有已生成的 APK。详见 [Mobile 首版](../apps/mobile/README.md)。

## 验证

`npm run typecheck` 包含 workspace/浏览器边界检查和两套 TypeScript 检查。仅 Web + Runtime 使用 `npm run install:runtime` 安装根目录工具、Server/Web/CLI 和共享 packages，排除 Desktop/Mobile 工作区；使用 `npm run typecheck:runtime` 检查对应源码。Electron、electron-builder、@electron/rebuild 由 `apps/desktop` 声明，完整桌面开发继续使用 `npm ci`。单一锁文件保留所有工作区的锁定版本，筛选安装不会下载未选工作区的专属依赖。
npm test 使用 Node ABI 执行 Vitest；Electron 不再需要重建 SQLite。
npm run verify:remote 在临时数据目录启动独立 Server，通过真实浏览器、Electron 和 CLI 验证登录、同账号共享会话、Web 刷新恢复、ZIP 上传、产物下载、令牌隔离和 Desktop 退出后服务继续。
浏览器未安装时可先安装 Playwright 浏览器，或设置 PLAYWRIGHT_CHANNEL=chrome 使用本机 Chrome。
设置 AGENT_DESKTOP_EXECUTABLE 为应用可执行文件路径，可验证实际打包应用。
npm run verify:desktop-package 检查 macOS app.asar 与资源目录不存在 Server、SQLite、MCP 或 Runtime Pack。

历史测试当前仍有两项业务基线不一致：bridge-controller 的 mcp-server.test Fixture 缺少 tools 字段；capability-discovery 期望过滤 disabled Skill，但当前业务实现仅检查绑定、有效性和兼容性。本次不改变这两处既有业务语义。
