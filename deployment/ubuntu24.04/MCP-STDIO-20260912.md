# Linux stdio MCP 修复记录（2026-09-12）

## 问题与修复

已核对外部团队报告和当前源码：原 `McpManager.createTransport()` 调用的 `stdioSandboxCommand()` 只接受 macOS，因此 Linux 的 builtin-memory 及其他 stdio MCP 在启动前失败。`testMcpServer()` 丢弃原因。旧功能烟测直接使用 SDK 启动 memory，绕过该缺陷所在的 Runtime manager。

- stdio MCP 复用 execution 包的 Linux bubblewrap 挂载沙箱；系统和捆绑 Runtime 只读，只绑定当前实例的数据目录可写，保留 MCP 原有联网语义。
- 使用现有 user/agent/server 路由隔离目录，HOME 与临时目录固定在实例内；检查 cwd 和实例路径的符号链接逃逸，保留 macOS 文件写入沙箱。Linux Runtime 安装路径为符号链接时，同时提供只读路径别名。
- 沙箱缺失、系统拒绝、命令不可用等诊断通过可选 `errorCode` / `message` 返回，保留原 `status` 枚举以兼容旧客户端。内置 Web/Desktop 共用设置界面显示诊断；Curry 等外部客户端需要读取新字段。
- 子进程 stderr 持续排空，仅保留最多 8192 字符用于已知沙箱错误分类；响应与连接状态使用固定诊断，不原样回传第三方错误、URL、参数或凭据。
- 平台归档验证增加真实 `mcp-server.test`；功能烟测改为经 Runtime 执行 `mcp_load`、记忆写入和读取，并重启 Runtime 后验证持久化。Ubuntu 打包入口加入定向回归。

## 验证

- macOS arm64 / Node 24.20.0：7 个定向测试文件，22 项通过、2 项 Linux 专用用例按平台跳过。真实 memory、自定义 stdio、路径逃逸、错误响应、实例管理及 macOS Bash 沙箱均覆盖。
- Debian 12 x64 容器 / Node 22.23.2 / bubblewrap 0.8.0：以普通 `node` 用户运行 4 个文件，15 项全部通过。真实 memory 读写、进程重建持久化、跨用户和私有/共享隔离通过；自定义 stdio 只能写当前实例，无法读取凭据目录、修改 Runtime 或写入实例外部。Linux Bash 的网络开关及进程树取消也通过。
- 容器初始 `/proc` 挂载受限时，真实测试失败并返回 `MCP_SANDBOX_DENIED`。测试容器随后允许嵌套 namespace/proc 挂载（SYS_ADMIN、seccomp/systempaths 测试配置），产品沙箱参数没有降低。
- Server/Web 构建、类型检查与定向 ESLint 检查通过。
- macOS 临时解压目录覆入本轮 Server/Admin 构建，完整 `verify-runtime-features.mjs` 通过，包含 Runtime 管理的记忆工具调用和整个服务重启后的读取。该目录是验证构建，不是新发行包。
- 上述 macOS 临时目录重新归档后，`verify-platform-runtime.mjs` 的离线安装和新增 builtin-memory 连接检查通过；没有覆盖原发行归档。
- Debian 容器组装本轮 Server/Admin 构建后，同一完整功能烟测也通过（测试解释器为 Node 22.23.2 / Python 3.11.2）。这是 Linux 源码构建验证，不是生产 Lock 指定解释器或 Ubuntu 发行包验收。
